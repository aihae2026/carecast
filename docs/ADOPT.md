# CareCast 도입 가이드 — 다른 기관이 따라 하려면

> 같은 내용을 읽기 좋은 한 장으로 만든 HTML 판이 `docs/adopt-published.html`에 있습니다.
> **원본은 이 파일입니다** — 내용을 고치면 그 HTML 도 같이 고칩니다.

> 이 문서는 **다른 요양원·복지시설이 같은 것을 자기 현장에 놓으려 할 때** 읽는 것입니다.
> 개발자용 실행 방법은 `README.md`, 소스에서 개발하는 법은 `docs/DEVELOPER.md`에 따로 있습니다.
>
> 여기 적힌 것은 **한 노인요양원에서 실제로 돌고 있는 구성**입니다. 좋아 보이는
> 구성을 상상해서 적지 않았고, 우리가 겪지 않은 일은 겪었다고 적지 않았습니다.
> 대신 **우리가 밟은 지뢰**(6번)를 자세히 적었습니다. 이 문서에서 제일 값나가는 부분이 그것입니다.

---

## 1. 이 시스템이 하는 일

요양원에서 **매일 정해진 시각에 나가는 방송**(아침 방송 · 체조 · 점심 · 저녁 · 저녁 마무리 등)을
PC 한 대가 알아서 내보냅니다. 사람은 예외적인 것만 손댑니다.
몇 개를 어떤 시각에 내보낼지는 기관이 화면에서 정하는 것이라, 여기 적은 것은 우리 현장의 예입니다.

- 정시 방송을 **시각·순서·볼륨까지 정해 두고** 자동 실행합니다(안내 음성 → 음원 → 차임벨 같은 묶음).
- 급한 안내는 화면에서 문장을 적으면 그 자리에서 음성으로 나갑니다.
- **"11시에 점심 안내 방송 예약해줘"처럼 말하듯 적으면** AI가 초안을 만듭니다.
  다만 **사람이 확정 버튼을 눌러야 실제 예약이 됩니다**(7번 참고).
- 방송이 안 나갔으면 스스로 알아채고 화면에 띄웁니다.

## 2. 필요한 것

| 항목 | 우리가 쓰는 것 | 비고 |
|---|---|---|
| PC | Windows 10/11 데스크톱 1대 | 방송 시간에 켜져 있어야 합니다. 사양은 높을 필요 없습니다 |
| 스피커 | PC에 연결된 시설 내 방송용 출력 | **소리는 이 PC의 스피커로 나갑니다**(6-1을 반드시 읽어 주십시오) |
| 마이크 | 있으면 좋습니다 | 눌러서 말하는 생방송용. 없어도 나머지는 다 됩니다 |
| Node.js | 설치본에는 **Node 24 가 동봉**되어 따로 깔지 않습니다(소스로 띄울 때만 직접 설치) | 설치 파일이 없으면 잡아 줍니다 |
| Python | 설치본에 동봉(소스로 띄울 때만 직접 설치) | 차임벨 · 서버 스피커 재생 · 마이크가 파이썬으로 돕니다 |
| 안내 음성 모델 | 설치본에 동봉(Supertonic 3, 139MB · 소스로 띄울 때는 `npm run setup:tts`) | 글자를 이 PC 안에서 목소리로 바꿉니다 — 이용 조건은 `LICENSES.md` |
| 인터넷 | 필요 | 다만 **끊겨도 음원 방송은 나갑니다**(6-6) |
| 브라우저 | Microsoft Edge | 설치가 바탕화면 실행 파일에 Edge를 물려 줍니다 |

**돈이 드는 것은 없습니다.** 음성 합성은 이 PC 안에서 하고, 날씨는 무료 경로를 씁니다. 배경음악·영상은 저작권이 확인된 파일을 이 PC 에 등록해 씁니다.
무료 음원 사이트(예: Pixabay)는 **예시일 뿐이며 CareCast 는 어떤 음원의 권리도 보증하지 않습니다** — 곡 페이지 주소와 받은 날짜를 출처 칸에 남기고, 받은 파일을 그대로 나눠 주지 마십시오(자세히는 `LICENSES.md` 5절, 약관 <https://pixabay.com/service/terms/>).
AI 초안 기능만 Google Gemini 키가 필요한데, 그 기능을 안 쓰면 키 없이도 전부 동작합니다.

## 3. 설치

### 설치 파일(`CareCast-Setup.exe`)로 설치할 때 — 대부분 이쪽

코드 서명 인증서가 없어 처음 열 때 경고가 뜹니다(2026-09-17 노트북 실측). 위험 표시가 아니라 「처음 보는 게시자」라는 뜻입니다.

1. 파란 **「Windows의 PC 보호」** 창 → 글자 **「추가 정보」** 를 누릅니다.
2. 아래에 생긴 **「실행」** 을 누릅니다(처음에는 「실행 안 함」만 보입니다).
3. **V3 「앱 격리 검사」** 창이 뜨면 끝날 때까지 기다립니다(최대 몇 분).
4. 「이 앱이 디바이스를 변경할 수 있도록 허용하시겠어요?」 → **「예」**.
5. 설치가 끝나면 초기 설정 8단계가 뜹니다. 7단계 「접속 주소」의 **휴대폰 접속 허용하기**에서 뜨는 창에도 「예」.

### 저장소 소스로 설치할 때 — 현장 PC 방식

저장소를 받은 폴더에서 **`CareCast-설치.bat`을 더블클릭합니다.** 이 파일 하나가 다 합니다:

1. Node.js·Git이 있는지 보고, 없으면 안내하거나 설치합니다
2. 최신 코드를 받습니다
3. 패키지를 설치하고 화면을 빌드합니다
4. 바탕화면에 "CareCast 시작.bat"을 만듭니다
5. **작업 스케줄러에 등록합니다** — 로그인하면 저절로 뜹니다
6. 스케줄러용 파일도 따로 만듭니다(한글 파일명이면 스케줄러가 경로를 못 읽습니다)

설치가 끝나면 PC를 재시작합니다. 이후로는 **켜면 저절로 뜹니다.**

**이 파일은 몇 번을 실행해도 안전합니다.** 이미 쓰고 있던 기관이라면 **한 번만 더** 실행하면
됩니다 — 시작 파일이 새 구조로 바뀝니다(6-9). 그 뒤로는 필요 없습니다.
(자동 업데이트는 **기본으로 꺼져 있습니다** — 켜는 법·끄는 법은 `README.md` 「업데이트」.)

개발용으로 만져 볼 PC라면 `carecast-개발환경-설치.bat`이 따로 있습니다.

## 4. 처음 설정할 것

브라우저에서 `http://localhost:3001` — 같은 와이파이의 폰·태블릿에서는 설치 화면에 찍히는
네트워크 주소(`http://192.168.x.x:3001`)로 들어갑니다. 관리자 화면은 그 주소 뒤에 `/admin`.

**설정은 전부 그 PC의 DB에 있고 git으로 따라오지 않습니다**(6-5). 그러니 새 기관은 아래를
처음에 한 번씩 지나가야 합니다. 위에서 아래 순서가 그대로 의존 순서입니다 — 소리가 안 나오는
PC에 예약을 넣어 봐야 확인할 방법이 없습니다.

### 4-1. 반드시 해야 하는 것 (안 하면 안 돌아갑니다)

| # | 무엇 | 어디서 | 안 하면 |
|---|---|---|---|
| 1 | **출력 장치** | 설정 → 음량 및 TTS | 아무 소리도 안 납니다. 화면은 성공으로 뜹니다(6-1) |
| 2 | **하루의 시작·끝** | 아래 5번(켜기는 BIOS, 끄기는 설정 → 시스템 설정 → 「방송 운영 · 자동화」의 자동 종료) | 꺼진 PC는 아무것도 안 합니다 |
| 3 | **정시 방송 5종** — 아침 방송·체조·점심·저녁·저녁 마무리. 각각 **켜기 / 시각 / 요일 / 읽을 문장** | 자동순서 탭 | 새로 설치한 PC는 방송이 하나도 안 나갑니다 |
| 4 | **볼륨** — 안내 음성·음원·BGM·영상·TV 다섯이 따로입니다 | 설정 → 음량 및 TTS | 방송마다 크기가 들쭉날쭉합니다 |
| 5 | **지역값** — 기상청 격자 `nx`·`ny`, 생활기상 `areaNo`, 자외선 관측소, 미세먼지 측정소 | 설정 → AI · API 연동 | **날씨가 남의 동네 것으로 나갑니다.** 기본값(서울)이 그대로 남아 있으면 조용히 틀립니다 |
| 6 | **합성 음성 고지** — 안내 방송이 컴퓨터 목소리라는 것을 **방송을 듣는 어르신이 알아볼 수 있게** 게시합니다(입소 안내문은 함께) | 견본: `docs/SYNTHETIC-VOICE-NOTICE.md` (뽑아서 붙이면 됩니다) | **안내 음성 모델의 이용 조건 위반입니다**(라이선스 (e) — `LICENSES.md`). 의료 조언 방송·동의 없는 사칭도 금지입니다 |

**기본 방송 문안은 종교 중립입니다.** 식사 전에는 「식사 안내」, 저녁 첫 안내는 「마음 안정 시간」으로
나갑니다. 기도 단계는 **「기도·묵상 시간(선택)」이라는 이름으로 들어 있지만 기본으로 꺼져 있습니다.**
종교 시설은 자동순서 탭에서 그 단계를 켜고, 안내 문장과 음원(기도문 녹음 등)을 **직접 넣으십시오.**
저장소에는 어느 종교의 기도문도 예시로 들어 있지 않습니다. 방송 이름(「아침 방송」·「저녁 마무리」)도
같은 탭에서 바꿀 수 있습니다.

### 4-2. 기관 이름과 방송 대기화면 문구

방송 중에 뜨는 전체 화면의 큰 글씨(윗줄 표어, 아랫줄 기관 이름)는 **설정 화면에서 넣습니다.**
설정 → 시스템 설정 → 「방송 운영 · 자동화」 → **방송 화면 문구**.

**처음 설치하면 비어 있습니다.** 남의 기관 이름을 기본값으로 넣어 두면 켜자마자 그 이름이 홀 TV에
걸리기 때문에 일부러 비웠습니다. 비어 있는 줄은 아예 안 그리므로, 넣기 전이라고 화면이 이상해지지는
않습니다. 넣고 나면 홀 화면을 한 번 새로고침합니다(화면이 열릴 때 한 번 읽습니다).

소스를 고치고 다시 빌드할 일은 없습니다 — 2026-09-05까지는 코드 두 줄을 고치라고 안내하고 있었습니다.

### 4-3. 쓸 거라면 (안 써도 나머지는 다 됩니다)

- **AI 초안**(말로 예약 넣기) — Gemini 키
- **날씨·기상특보** — 기상청 키(공공데이터포털 + apihub 둘 다)
- **조명·TV 자동 제어** — SwitchBot 토큰
- **일정 안내** — Google Calendar 연동

키는 `.env` 파일이 아니라 **화면에서 넣는 것이 정본**입니다.

### 4-4. 마지막에 반드시 — 귀로 듣습니다

1. 정시 방송 하나를 **실제 시각이 오기 전에 손으로 눌러 보십시오.**
2. **스피커에서 소리가 났는지 귀로 확인합니다.** 화면의 "성공"과 갈리는 경우가 있습니다(6-1).
3. 홀 뒤쪽까지 들리는지 걸어가서 듣고, 그 자리에서 볼륨을 맞춥니다. 안내 음성과 배경음악을
   따로 들어 봅니다 — 음악에 목소리가 묻히는 것이 가장 흔한 첫 실패입니다.
4. **카카오톡 알림음을 꺼 두십시오**(6-10). 이 PC의 다른 앱 소리도 같은 스피커로 나갑니다.

## 5. 현장에서 어떻게 돌리고 있나 — 켜기와 끄기

우리는 사람이 매일 켜고 끄지 않습니다. 이렇게 묶어 뒀습니다:

```
아침  메인보드 BIOS 자동 부팅(정해진 시각 전원 ON)   ← 소프트웨어가 아니다
        → 로그인 → 작업 스케줄러가 시작 파일 실행
          → 서버 기동(그때 DB를 한 벌 백업한다) · Edge가 방송 화면을 자동으로 엶
낮      → 정시 방송 · 누락 감시
저녁  18:21  CareCast가 PC를 자동 종료(auto_shutdown_time)   ← 이건 소프트웨어가 한다
밤      기계가 꺼져 있다
```

시각 두 개는 기관이 정합니다. **끄는 시각은 관리자 화면에서** 바꾸고(`auto_shutdown_time`),
**켜는 시각은 BIOS에서** 바꿉니다. 우리 현장의 지금 값은 종료 18:21입니다.

> 기록 정리(방송 365일 · 경보 180일 · 점검 90일)는 백업 직후에 돕니다. 백업 시각(`backup_time`,
> 기본 04:30)에 PC가 꺼져 있으면 그 시각 백업은 건너뛰고 **다음 기동 때 한 벌 뜹니다** —
> 하루 한 벌이 남는 것은 같습니다.

### 소프트웨어만으로 PC를 켤 수는 없습니다

설치 패키지에 넣어 자동화할 수 있는지 확인했고, **켜는 것은 안 됩니다**라는 결론입니다.
완전히 꺼진 PC에서는 OS가 안 돌아가므로 어떤 프로그램도 자기를 깨울 수 없습니다.
길은 셋뿐이고 셋 다 PC 바깥 또는 BIOS를 건드려야 합니다.

| 방법 | 되나 | 무엇이 필요한가 |
|---|---|---|
| **BIOS 자동 부팅**(RTC 알람) — 우리가 쓰는 것 | **됩니다** | 메인보드에서 사람이 한 번 켭니다. 이름은 보드마다 다릅니다(`RTC Alarm Power On`, `Wake on RTC`, `Power On by Alarm`). 표준이 없어 설치 프로그램이 못 건드립니다 |
| **Wake-on-LAN** | 됩니다 | 매직 패킷을 보낼 **다른 기기**가 늘 켜져 있어야 합니다(공유기·NAS·스마트플러그). 게다가 완전 종료 상태에서 받으려면 결국 BIOS와 랜카드 설정을 켜야 합니다 — BIOS를 만지는 건 같은데 기계가 하나 더 늡니다 |
| **완전 종료 대신 최대 절전 + 작업 스케줄러 깨우기** | **소프트웨어만으로 됩니다** | 대신 "완전히 꺼진다"를 포기합니다. 작업 스케줄러의 *컴퓨터의 절전 모드 해제* 옵션은 절전·최대 절전에서만 깨우고 **완전 종료(S5)에서는 못 깨웁니다.** 전원 옵션에서 깨우기 타이머도 허용해야 합니다 |

그래서 **패키지는 끄는 것만 자동화하고, 켜는 것은 이 문서가 절차로 안내합니다.**
"밤에 기계가 꺼져 있다"가 우리 안전 설계의 바닥이라(6-8) 최대 절전으로 바꾸지 않았습니다.

### 죽으면 누가 살리나

시작 파일이 서버를 **스스로 다시 띄웁니다.** 포트만 보는 게 아니라 `/api/health`로
"스케줄러가 실제로 돌고 있는가"까지 5초마다 보고, 3연속 약 15초 실패해야 재시작합니다
(한 번 걸렀다고 죽이면 멀쩡한 서버를 끊습니다).

시작 파일은 **껍데기와 알맹이 두 층**입니다. 껍데기는 다시 안 바뀌고, 감시 로직이 든 알맹이는
저장소가 원본이라 코드를 받을 때(`git pull`, 또는 켜 둔 경우의 자동 업데이트 — 기본 꺼짐) 함께
갱신됩니다 — 그렇게 만든 경위가 6-9입니다. 꼭 읽어 보십시오.

백업과 복구 절차는 `docs/BACKUP.md`에 따로 적혀 있습니다.

## 6. 우리가 밟은 지뢰 — 여기부터가 진짜입니다

같은 것을 놓으려는 기관이 **똑같이 밟을 만한 것들**입니다. 전부 실제로 겪었습니다.

### 6-1. 소리는 브라우저가 아니라 **서버 PC 스피커**로 나갑니다

안내 음성도 음원도 **서버가 도는 그 PC의 스피커**에서 납니다. 화면을 보는 기기(폰·태블릿)에서
나는 게 아닙니다. 그래서 **스피커가 안 꽂혀 있어도 화면에는 "성공"으로 뜹니다.**
설치 직후 첫 확인은 반드시 귀로 합니다. 재생 명령을 만드는 자리는 `server/services/audioBackend.js` 한 곳입니다.

### 6-2. **새로고침 안 한 방송 화면**이 멀쩡한 방송을 실패로 만듭니다

코드를 갱신하면 서버만 바뀌고 **이미 열려 있는 창은 옛 코드 그대로**입니다. 옛 창은 서버가
기다리는 생존 신호를 보낼 줄 모릅니다. 그 상태에서 누가 새 창을 잠깐 열었다 닫으면, 서버가
옛 창을 **유령으로 오판**해서 정상적으로 나간 방송을 이력에 실패로 적고 무음 경보를 띄웁니다.

→ **코드를 갱신했으면 열려 있는 방송 화면을 F5 합니다.** 이 상태인지는 `/api/health`의
`localClients`와 `localClientsAlive`가 다른 것으로 알 수 있습니다.

### 6-3. "포트가 열려 있다"는 살아 있다는 뜻이 아닙니다

프로세스는 떠 있는데 스케줄러만 멈춘 적이 있습니다. 포트만 보는 감시는 그걸 못 잡습니다.
그래서 `/api/health`가 **마지막 스케줄러 tick이 3분 넘게 없으면 503**을 줍니다.
감시를 새로 만든다면 "돌고 있는가"를 보게 만드십시오.

### 6-4. 한글 파일 이름·장치 이름이 깨진 채로 저장되면 조용히 망가집니다

한국어 Windows의 기본 코드페이지(CP949)와 UTF-8이 어긋나는 자리가 여러 곳 있습니다.
깨진 출력장치 이름이 한 번 저장되자 **모든 방송이 엉뚱한 장치로 나갔고**, 화면상으로는
아무 문제가 없었습니다. 업로드한 음원 파일 이름도 같은 함정이 있습니다(맥·아이폰에서 올린 이름이 특히 그렇습니다).

→ 이름을 저장하는 경로에는 반드시 정규화를 한 겹 둡니다. 우리는 저장 전에 걸러내고,
이미 들어간 것은 되돌리는 스크립트를 따로 만들었습니다.

### 6-5. **설정과 예약은 git에 없습니다** — PC를 옮기면 안 따라옵니다

예약·즐겨찾기·음원은 전부 DB 파일에 있고, 그 파일은 저장소에 올리지 않습니다(개인정보·용량 때문입니다).
그래서 다른 PC에 설치하면 **화면은 "예약이 사라졌다"처럼 보입니다.** 실제로는 처음부터
없었던 것입니다. 우리는 이걸로 세 번 헛걸음했습니다.

→ 옮길 때는 DB 파일을 **`-wal` 파일까지 함께** 복사합니다. 이걸 빠뜨리면 최근에 바꾼 설정이 안 옵니다.
현장 설정을 새 PC의 기초값으로만 쓰고 싶으면 `scripts/make-site-baseline.cjs`가 그 일을 합니다.

### 6-6. 인터넷이 끊겨도 **안내 음성과 음원 방송은 나갑니다**

안내 음성은 이 PC 안에서 만듭니다(Supertonic 3 — 2026-09-21 부터). 예약 자체와 음원 파일 재생, 차임벨도 PC 안에서 끝납니다.
인터넷을 타는 것은 날씨·미세먼지·AI 문안과, 기관이 켠 경우의 Azure 음성(선택)뿐입니다.

→ 날씨가 들어가는 아침 방송은 인터넷이 끊기면 날씨 문장 없이 나갑니다.
"인터넷이 없어도 다 된다"고 말하지 말 것 — 우리 구조에서는 사실이 아닙니다.

### 6-7. AI가 만든 것은 **사람이 확정해야 방송됩니다**

말로 적은 예약은 AI가 초안까지만 만듭니다. 사람이 확인하고 누르기 전에는 방송될 방법이 없습니다.
파서가 헷갈린 것(오전/오후, 반복 여부, 방송 유형)은 **문장으로 되물어서 체크해야 확정 버튼이 열립니다.**

→ 조용한 오독이 현장에서 가장 찾기 어려운 실패입니다. 잔소리를 감수하고 되묻는 쪽을 택했습니다.
AI 기능을 더할 때도 이 구조(초안 분리 + 명시적 승인)를 기본값으로 두길 권합니다.

### 6-8. 밤에 기계를 꺼 두면 걱정거리 하나가 통째로 사라진다

우리는 저녁 18:21에 자동으로 끕니다. 켜지는 것은 다음 날 아침입니다. 그 사이에는
**방송이 물리적으로 불가능**합니다. 그래서 "새벽에 잘못 나가면 어쩌나" 하는 종류의 대비를
아예 안 만들었습니다. 위험한 시간대는 오히려 어르신이 깨어 있는 낮이고, 거기서 중요한 것은
오발송이 아니라 **누락(안 나감)**입니다. 감시를 그쪽에 걸었습니다.

이건 절약이 아니라 **설계입니다.** 기계가 꺼져 있는 시간을 길게 잡을수록 다뤄야 할 경우의
수가 줄어듭니다. 다른 기관도 24시간 켜 두기 전에 한 번 재 보길 권합니다.

### 6-9. **배치 파일에 한글을 쓰면 안 됩니다** — 5초마다 오류가 났습니다

이게 이 문서에서 제일 늦게 발견했고, 제일 값나가는 지뢰다(2026-09-04).

우리 현장 도스창을 받아 세어 보니 `'  ' is not recognized as an internal or external
command,`가 **3시간 56분 동안 2932번** 찍혀 있었습니다. 4.83초에 한 번 — 시작 파일 감시 루프가
`timeout /t 5`로 도는 주기 그대로입니다. **서버를 되살릴 유일한 루프가 매 바퀴 실패하고 있었습니다.**

원인을 재현해서 잡았습니다. **cmd는 배치 파일을 바이트 위치로 읽습니다.** 파일에 UTF-8 한글이
있으면 `goto`로 루프에 되돌아올 때 글자 중간에 떨어져, 글자 조각을 명령으로 실행합니다.
같은 루프를 조건만 같게 두고 나란히 돌린 결과다:

| 루프 파일 | 바퀴 | `is not recognized` | 시작 배너 |
|---|---|---|---|
| 한글이 든 UTF-8 | 333 | **1,672** | 안 뜸 |
| ASCII만 | 78 | **0** | 정상 |

한글을 CP949로 저장하는 것은 답이 아닙니다 — 그러면 편집기·git·다른 PC에서 깨진다(6-4).
**답은 배치 파일에 한글을 아예 안 쓰는 것입니다.**

→ 그리고 이걸 고치는 동안 더 깊은 문제가 드러났습니다. **시작 파일은 설치할 때 한 번 만들어지고
자동 업데이트가 갱신하지 않습니다** — 저장소에 없는 파일이라 `git pull`이 볼 수가 없습니다.
감시 방식을 고쳐도 현장에는 몇 달 묵은 판본이 계속 돈다는 뜻입니다.

그래서 **두 층으로 갈랐습니다.**

```
carecast-start.bat   껍데기 · ASCII 10줄 · 다시는 안 바뀐다
  ├ carecast-loop.next.bat 이 있으면 갈아 끼운다   ← 다음 부팅에 새 판본 적용
  └ carecast-loop.bat 을 부른다

carecast-loop.bat    알맹이 · 감시 루프 · ASCII만
  └ 원본은 scripts/carecast-loop.template.bat — git pull이 갱신한다
```

- 서버가 기동할 때 저장소 판본과 다르면 **옆에 깔아 두기만 합니다.** 도는 파일은 안 건드립니다 —
  **도는 중인 배치 파일을 덮어쓰면 cmd가 바이트 위치를 잃고 똑같은 오류를 낸다**(이것도
  실측했습니다). 크롬 같은 앱이 업데이트를 다음 실행에 적용하는 것과 같은 이유입니다.
- 깔기 전에 **그 판본이 성한지 먼저 봅니다** — 깨진 것을 깔면 다음 부팅에 현장이 안 뜹니다.
- 서버는 기동할 때 지금 도는 감시 파일도 읽어 봅니다. ASCII가 아닌 글자·캐럿·보이지 않는
  공백·`/api/health` 판정·되살리는 길을 보고, 이상하면 도스창이 아니라 **화면 경보로**
  올린다(`server/services/startBatCheck.js`).

→ **현장에서 `CareCast-설치.bat`을 딱 한 번만 더 실행하면 됩니다.** 그 뒤로는 감시 규칙을
고쳐도 자동으로 따라옵니다.

### 6-10. 이 PC의 **다른 앱 소리도 같은 스피커로** 나갑니다

정시 방송의 소리는 대부분 현장 PC의 방송 화면이 냅니다. 안내 음성·차임벨·마이크도 이 PC에서
납니다. 이것들은 전부 **Windows 기본 출력 장치**를 쓰고, 그 장치가 곧 홀 스피커입니다.
그러니 같은 PC에 깔린 카카오톡 알림음도 홀로 나갑니다. 실제로 겪었습니다.

→ **카카오톡 쪽에서 알림음을 끈다**(볼륨 믹서에서 0으로 두는 것으로 보강). 화면 팝업은
남으니 직원이 메시지를 놓치지 않습니다. 카톡 소리를 꼭 들어야 하면 Windows의
*앱 볼륨 및 장치 기본 설정*에서 카톡만 다른 출력 장치(모니터 스피커 등)로 돌립니다.

**"방송 중일 때만 다른 앱을 음소거"는 만들지 않았습니다.** 방송 소리의 대부분이 브라우저에서
나기 때문에 "CareCast 아닌 것 전부 음소거"는 방송 자신을 죽입니다. 카톡만 지목해서 방송
중에만 끄는 것도, 알림음이 울리는 그 순간에 오디오 세션이 생기므로 **첫 소리는 원리적으로
못 막습니다.** 조건부로 끄는 것보다 **그냥 꺼 두는 것이 더 단순하고 더 확실하다** — 홀
스피커는 방송을 안 할 때도 홀에 걸려 있습니다.

## 7. 이 시스템이 하지 않는 일

기대를 미리 맞춰 두는 편이 낫습니다.

- **클라우드가 없습니다.** 서버도 데이터도 그 PC 안에 있습니다. 밖에서 접속하려면 따로 준비해야 합니다.
- **PC가 꺼져 있으면 아무것도 안 합니다.** 예약은 그 PC의 시계로 돕니다.
- **여러 건물·여러 층을 나눠 방송하는 기능은 없습니다.** 출력은 그 PC에 물린 하나입니다.
- **어르신 명단·건강 기록을 관리하는 시스템이 아닙니다.** 다만 **직원이 입력한 개인정보는 남을 수 있습니다** —
  방송 문안·예약·자동순서 안내 문구, 연결한 Google 캘린더 일정 제목, 방송 기록(문안 포함, 기본 365일 보관)에
  어르신·직원 이름 등이 들어가면 그 PC 안에 그대로 남습니다. 주민등록번호·휴대폰번호·생년월일은 저장·방송 전에 막습니다.
- **외부로 나가는 경우가 있습니다.** 외부 AI(Gemini)를 쓰면 예약 해석·문구 짓기·자막 다듬기 때 문안이 Google 로 갑니다 —
  번호는 지우고 「김○○ 어르신」처럼 호칭이 붙은 이름은 가려서 보내지만, **호칭 없이 쓴 이름은 못 가립니다.**
  Azure 음성을 켜면 방송 문안이 Microsoft 로 갑니다. **보내기 전에 문안을 먼저 확인**하시고, 실명 대신 호실(예: 201호 어르신)을 쓰는 운영 규칙을 권합니다.
- **의료·응급 시스템이 아닙니다.** 안내 방송을 대신할 뿐입니다.

세어서 한 장으로 만듭니다. 세는 규칙과 집계 기간을 그 안에 같이 적습니다.
