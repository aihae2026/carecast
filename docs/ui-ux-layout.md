# 화면 레이아웃 규격 (CareCast 관리자 화면)

> 왜 이 문서가 생겼나: 2026-09-11 사용자 지적 — *"너무 옆으로 가로 횡으로 퍼져보이게끔 하지마.
> 전체적인 여백을 양옆에 두던지. 너무 퍼져보이니까 불편하잖아 보기에도."*
>
> 이 저장소는 중단점(390·834·1024·1440)은 정해 뒀지만 **최대 폭은 쉬운 화면에만** 있었다
> (`SimpleMode.jsx:89`). 관리자 화면은 없어서 모니터가 넓어지는 만큼 카드가 늘어났다.
>
> **값을 여기 적지 않는다.** 실제 값은 `src/index.css` 의 `.page-shell` 과
> `tailwind.config.js` 의 `screens` 가 정본이고, 이 문서는 **왜 그 값인지**를 적는다.
> `server/test/layout-max-width.test.js` 가 이 규칙이 실제로 쓰이는지 고정한다.

---

## 1. 뼈대 — 사이드바 + 본문

```
┌──────────┬──────────────────────────────────────────────┐
│ 사이드바  │            본문 (가운데 정렬, 최대 1180)        │
│  240px   │   ← 여백 →  [ 1180px 콘텐츠 ]  ← 여백 →        │
└──────────┴──────────────────────────────────────────────┘
```

| 요소 | 값 | 근거 |
|---|---|---|
| 사이드바 폭 | **240px** (`w-60`) | `Sidebar.jsx`. 일반적인 대시보드 SaaS 의 사이드바는 220–260px 다 |
| 본문 최대 폭 | **1180px** (`.page-shell`) | 디자인 캔버스의 데스크톱 폭 1440 − 사이드바 240 = 1200. 좌우 여백을 빼면 딱 이 폭이다. **즉 캔버스 위에서는 지금과 한 픽셀도 안 달라지고**, 그보다 넓은 모니터에서만 가운데로 모인다. `GuideMapPage.jsx:109` 가 이미 같은 값을 쓴다 |
| 좌우 여백 | 24px, 1024 이상 32px | `px-6 laptop:px-8` |
| 상하 여백 | 28px (`py-7`), 하단 96px | 하단은 떠 있는 '방송 화면' 버튼에 가리지 않기 위해서다 |

**한 줄이 너무 길면 읽기 어렵다.** 본문 글줄이 1200px 를 넘으면 눈이 다음 줄 첫 글자를
못 찾는다 — 이것이 폭을 묶는 진짜 이유이고, 미관 문제가 아니다.

## 2. 세로 리듬 — 8의 배수

| 쓰임 | 값 | Tailwind |
|---|---|---|
| 화면 블록 사이 | 20px | `space-y-5` / `gap-5` |
| 카드 안 구역 사이 | 12px | `mb-3` |
| 카드 안 줄 사이 | 8px | `space-y-2` |
| 카드 안쪽 여백 | 20px | `card-base` 의 `p-5` |

**섞어 쓰지 않는다.** `gap-4`·`gap-6` 를 화면마다 다르게 쓰면 같은 종류의 카드가 화면마다
다른 간격으로 놓여 정돈돼 보이지 않는다.

---

## 3. 열 나눔

| 상황 | 규칙 |
|---|---|
| 두 덩어리(보조 + 주) | `lg:grid-cols-3` 에 `1 : 2` — 대시보드 윗줄·아랫줄이 이 모양이다 |
| 나란한 지표 타일 | `grid-cols-5`(최대). 여섯 개를 넘으면 두 줄로 접는다 |
| 좁은 화면 | 1열로 쌓되 **읽는 순서를 지킨다.** 주 내용이 보조보다 먼저 오게 한다 |

**한 줄에 5개를 넘기지 않는다.** 1180px 에서 6칸이면 한 칸이 180px 아래로 내려가
한국어 라벨("자동방송")이 줄바꿈된다.

## 4. 글자

| 쓰임 | 크기 | 무게 |
|---|---|---|
| 화면 제목 | 20px (`text-xl`) | bold |
| 화면 설명 | 14px (`text-sm`) | normal, `text-cc-sub` |
| 카드 제목 | 14px (`text-sm`) | semibold |
| 본문 | 13–14px | normal |
| 보조 설명 | 11px (`text-[11px]`) | normal, `text-cc-sub` |
| 숫자 | `.nums` (tabular) | — |

**숫자는 반드시 `.nums`.** 폭이 들쭉날쭉하면 표가 흔들려 보인다.

## 5. 상태 표시

- **색만으로 상태를 구분하지 않는다**(UX-42). 색 + 글자 + (필요하면) 아이콘을 함께 쓴다.
- 상태 어휘는 넷이다 — **정상 / 미설정 / 연결 끊김 / 확인 불가**.
  값을 못 읽었으면 **가짜 정상을 만들지 않고** '확인 불가'로 둔다(`src/lib/systemStatus.js`).
- 뱃지는 `whitespace-nowrap` 이다. 좁은 칸에서 "자동"이 "자/동" 으로 쪼개진 적이 있다.

## 6. 참고한 것과 그러지 않은 것

**참고**: 사이드바형 대시보드 SaaS 의 공통 규격 — 사이드바 220–260px, 본문 최대 폭
1100–1280px 가운데 정렬, 8px 배수의 간격, 카드 12–16px 라운드에 옅은 그림자.
이 저장소가 이미 그 범위 안에 있었고(`card-base` 16px 라운드, 그림자 6%), **빠진 것은
최대 폭 하나뿐**이었다.

**그러지 않은 것**: 색·타이포·둥글기 체계를 새로 들여오지 않았다. 이미
`tailwind.config.js` 의 `cc.*` 와 `src/styles/tokens.css` 두 벌이 있고, 세 번째를
만들면 "어느 것이 진짜냐"가 생긴다. 이 문서는 **배치 규칙만** 정한다.

---

## 7. 새 화면을 만들 때

1. 최대 폭을 직접 적지 않는다. `AdminMode` 안에 들어가면 `.page-shell` 이 이미 걸려 있다.
2. 바깥 감싸개는 `space-y-5`, 제목은 `text-xl font-bold` + 설명 한 줄.
3. 카드는 `card-base`. 새 그림자·라운드를 만들지 않는다.
4. 한 줄에 다섯 칸을 넘기지 않는다.
5. 값을 못 읽는 상태를 먼저 설계한다 — 로딩 · 빈 데이터 · 연결 끊김 · 확인 불가.
