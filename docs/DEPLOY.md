> 내부 요구사항 문서의 **G 구획(DEP-01 ~ DEP-10, 공개판에는 없음)** 이 물은 열 가지에 답하는 문서입니다.
> 각 답에 **어디까지 확인했는지**를 붙였습니다.
>
> | 표식 | 뜻 |
> |---|---|
> | `[구현]` | 코드·설치 파일이 그렇게 쓰여 있다 |
> | `[시험]` | 우리가 돌려서 초록이다 |
> | `[실측]` | 현장에서 실제로 해 봤다 |
> | `[계획]` | 아직 안 했다 |
> | `[미확인]` | 모른다 |
>
> **절차 안내가 필요하시면 이 문서가 아닙니다** — 도입은 [ADOPT.md](ADOPT.md),
> 일상 관리는 [MANUAL-ADMIN.md](MANUAL-ADMIN.md), 백업은 [BACKUP.md](BACKUP.md) 입니다.
> 여기는 **배포 방식 자체를 정하기 위한 문서**입니다.

## 먼저 — 가장 중요한 두 가지

### ① 지금 이 설치 파일로는 **새 기관이 설치할 수 없습니다** `[구현]`

> **※ 정정(공개판):** 이 절은 2026-09-16 이전 기록입니다. 지금은 빈 PC 용 설치 파일
> `CareCast-Setup.exe`([PACKAGING.md](PACKAGING.md))가 있고, 소스로 받는 길은 README 「설치」의 `git clone` 입니다.
> `CareCast-설치.bat` 도 `.git` 이 없으면 `git pull` 을 건너뜁니다. 아래 내용은 당시 판단을 남겨 둔 것입니다.

`CareCast-설치.bat` 은 **첫 줄부터 `git pull origin main` 을 합니다**(당시 기준).
즉 **이미 저장소가 복제돼 있는 PC**를 전제로 한 **업데이트 도구**이지,
빈 PC에 처음 놓는 **설치 도구가 아닙니다.**

새 기관이 쓰려면 먼저 이것이 있어야 합니다:

| 필요한 것 | 지금 상태 |
|---|---|
| 저장소 접근 권한 | 공개 저장소입니다(`github.com/jung-svg/carecast`) — 누구나 받을 수 있습니다 |
| 첫 복제(`git clone`) 절차 | **없습니다** `[계획]` — 설치 파일에 그 단계가 없습니다 |
| 기관별 초기값 | `site-baseline.json`(만든 기관의 값)은 **공개판에 들어 있지 않습니다** — 처음 설정 마법사에서 넣습니다(§DEP-04) |

> **이것이 「새 기관 배포 패키지」가 미착수인 진짜 이유입니다.** 설치 파일이 없어서가
> 아니라, **있는 것이 다른 일을 하는 물건**이기 때문입니다.

### ② 여러 기관이 **같은 `main` 을 따라갑니다** `[구현]`

`autoUpdate.js` 는 **켜 둔 PC 에서만**(공개판 기본은 꺼짐 — `AUTO_UPDATE_ENABLED=1` 로 켬, README 「업데이트」)
10분마다 `origin/main` 을 보고 새 것이 있으면 받아서 재시작합니다.
**기관을 구분하지 않습니다.** 그러므로 지금 구조로 자동 업데이트를 켠 기관을 늘리면:

- 우리가 `main` 에 커밋하면 **자동 업데이트를 켠 모든 현장 PC가 10분 안에 그것을 받습니다.**
- 한 기관에서만 쓰고 싶은 수정도 **전부에게 갑니다.**
- 한 기관에서 터지는 버그를 **우리가 밀어 넣은 것**이 됩니다.

**기관이 둘이 되는 순간 정해야 하는 것**이고, 아직 안 정했습니다 `[계획]`.
갈래는 셋입니다 — 기관별 브랜치 · 판올림을 사람이 승인하는 방식 · 지금처럼 단일 `main`.
**권하는 것은 두 번째**입니다(현장 PC가 자동으로 받되, **어느 판**을 받을지는 사람이 정함).
다만 이건 **제안이지 결정이 아닙니다.**

## DEP-01 — 역할과 패키징 방식

**PC가 셋까지 나옵니다.** `[구현]` `[실측]`

| 역할 | 무엇을 하나 | 소리 |
|---|---|---|
| **현장 PC**(Windows 1대) | 프로그램·DB·스케줄러가 여기서 돕니다 | **여기서만 납니다** |
| **방송 화면**(그 PC의 크롬/엣지 창) | 예약 방송의 소리를 내는 창 | 예약 안내·음원·BGM·영상 |
| **원격 기기**(직원 폰·다른 PC) | 같은 망에서 브라우저로 접속 | **안 납니다**(보기·조작만) |

**소리 주체가 유형마다 다릅니다** — 「지금 방송」·마이크는 **PC 스피커**,
예약된 것은 **방송 화면**입니다. 그래서 창이 닫히면 예약이 무음이 됩니다.

**지금의 패키징**: 설치 파일이 `git pull` → `npm install` → `npm run build` 를 하고,
바탕화면 `CareCast 시작.bat` 과 **로그온 시 자동 시작** 작업을 만듭니다. `[구현]`
실행은 `node server/index.js` 이고 `dist/` 를 정적으로 서빙합니다.

> **권고**: 새 기관용으로는 **소스를 안 주는 방식**(빌드 산출물 + Node 런타임 동봉)이
> 맞습니다 — 지금은 현장 PC에 **개발 도구 일체(git·전체 소스·node_modules)** 가 깔립니다.
> `[계획]` 아직 안 만들었습니다.

## DEP-03 — 설치부터 첫 방송까지의 흐름

**지금 되는 것** `[구현]`
1. `CareCast-설치.bat` 실행 → Node·Git 확인 → 코드 받기 → 패키지 설치(5~15분) → 빌드
2. 바탕화면 `CareCast 시작.bat` + **로그온 자동 시작** 등록
3. 켜면 감시 루프가 서버를 띄우고 **방송 화면을 자동으로 엽니다**
4. 관리자 화면에서 **API 키**와 **방송 시각**을 넣습니다

**빠진 것** `[계획]`
- **첫 복제 단계**(§① 참조)
- **초기 설정 마법사** — 화면(`SetupWizard`)은 있지만 `UX-01` 이 선행 조건으로 걸려 있습니다
- **장치·연동 검사** — 스피커가 맞는지, 키가 유효한지 **한 번에 확인하는 화면이 없습니다**
- **첫 더미 방송** — *"소리가 나는지 안전하게 한 번 확인"* 하는 절차가 없습니다.
  지금은 진짜 방송을 내보내 보는 수밖에 없어서 **어르신들께 들립니다.**

> **DEP-03 에서 가장 아쉬운 것이 「첫 더미 방송」입니다.** 설치 직후에
> *"이 스피커에서 소리가 납니다"* 를 **어르신께 안 들리게** 확인할 방법이 필요합니다.

## DEP-04 — 무엇이 어디에 사나

| 무엇 | 어디 | 백업 |
|---|---|---|
| 프로그램·소스 | 설치한 폴더 | git |
| **사용자 데이터 전부** | `server/db/database.db`(+`-wal`,`-shm`) — 예약·이력·설정·**API 키** | 자동(아래) |
| 자동 백업 | `server/db/backups/` — 기동 시 1회 + 매일 04:30, **30일 보관** | 같은 디스크 |
| 업로드 음원·영상 | **`server/public/audio/<갈래>/`** — 디스크의 파일입니다(경로 단일 출처는 `domain/audioPaths.js`) | **안 됩니다** `[계획]` |
| TTS 캐시 | 임시 폴더 | 안 함(다시 만들면 됨) |
| 기관 초기값 | `server/config/site-baseline.json` — **공개판에는 없습니다**(현장에서 `scripts/make-site-baseline.cjs` 로 만듦) | git(개발 저장소) |

**두 가지를 짚습니다.**

**① 비밀키는 DB 안에만 있고 git 에 안 올라갑니다** `[구현]` `[시험]`
`site-baseline.json` 을 뽑을 때 그물 셋(이름 목록 · 이름 생김새 · 값 훑기)으로 거릅니다.
`auto_shutdown_time` 과 `audio_device` 도 일부러 뺍니다 — 남의 값을 심으면 조용한 오작동입니다.

**② 그런데 `site-baseline.json` 자체에 기관 정보가 들어 있습니다** `[구현]`
기상청 격자 좌표(기관 위치) · 방송 시각 7개 · **그대로 읽히는 방송 문안 16개** · 예약 6건.
**저장소를 공개하려면 이 파일을 빼고 커밋 이력에서도 지워야 합니다.** — 공개판은 이 파일을 빼고 이력 없이 새로 만들었습니다.
그리고 **새 기관에는 이 파일이 운영 현장 값으로 들어갑니다** — 기관마다 갈라야 합니다 `[계획]`.

**음원·영상은 백업 대상이 아닙니다.** DB만 백업됩니다. 디스크가 죽으면 **올린 음원이
전부 사라지고**, DB에는 그 파일을 가리키는 행만 남아 **무음 방송**이 됩니다. `[계획]`

## DEP-07 — 원격 접근

- 같은 망의 기기가 **그 PC 주소:3001** 로 붙습니다. `[구현]` `[실측]`
- **인증이 없습니다. 의도된 설계입니다** — 방송을 내보내야 하는 순간에 로그인을 요구하면
  그게 사고입니다. 대신 **외부에 열지 않습니다.**

  원격 접속 허용) **이 전제는 무효입니다.** 그때 다시 판단합니다.
- 방화벽: Windows 가 처음 실행 때 물으면 **개인 네트워크**를 허용하면 됩니다. `[구현]`

  (게스트망·AP 격리). 막혀 있으면 직원 폰에서 안 붙습니다 — **현장마다 다릅니다.**

## DEP-09 — 깨끗한 환경 점검

**계획과 결과를 구분해서 적으라는 항목입니다. 그래서 분명히 적습니다.**

> **실제 수행 결과: 없습니다.** `[계획]`
> **아무것도 없는 Windows PC에 처음부터 설치해 본 적이 없습니다.**
> 지금 돌고 있는 현장 PC는 개발하면서 **점진적으로** 갖춰진 것이라, 무엇이 이미 깔려 있어서
> 넘어간 단계인지 **가릅니다.**

**점검 계획** `[계획]` — 하려면 이렇게 합니다.

1. 깨끗한 Windows(가상 머신도 됩니다)에 **Node 없이** 시작
2. `CareCast-설치.bat` 만 놓고 실행 → **어디서 막히는지** 적습니다
   (지금 예상: 저장소가 없어 `git pull` 에서 막힙니다 — §①)
3. 막힌 지점마다 **사람이 한 일**을 적습니다. 그게 곧 빠진 설치 단계입니다
4. 설치 후 **소리가 나는지**를 어르신께 안 들리는 방법으로 확인
5. PC를 껐다 켜서 **자동 시작과 방송 화면 자동 열림**을 봅니다
6. 예약 하나를 넣고 **시각이 지나갈 때 실제로 나가는지** 봅니다

**이 여섯 중 2~3번이 이 항목의 핵심입니다** — 「무엇이 빠졌는지」는 **해 봐야만** 나옵니다.
