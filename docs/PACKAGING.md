# 다른 기관에 배포하려면 — 포장·초기설정·제출 검토

## 2026-09-16 정정: 배포 대상은 Windows 설치 EXE

사용자는 압축을 직접 풀어 BAT를 실행하는 형태가 아니라 **CareCast-Setup.exe 하나로 설치**하기를 요청했다. 아래 ZIP 권고는 과거 검토이며 현재 결정이 아니다. 설치 EXE는 Electron 전환과 별개다. 기존 Node 서버 + 브라우저를 그대로 설치하므로 브라우저 기능을 잃지 않는다.

- 결과: `release/CareCast-Setup.exe`. Node/Python(numpy), 안내 음성 모델(Supertonic 3), 서버 의존성, 빌드 화면 포함.
- 한국어 설치 마법사, 사용자별 설치, 바탕화면 바로가기. 로그인 자동 시작은 선택 항목이다.
- 재설치/제거 전 해당 설치 경로의 감시 CMD와 Node만 종료한다. 다른 Node와 포트 주인은 종료하지 않는다.
- 사용자 DB·음원·환경설정은 배포에 넣지 않으며 제거할 때도 보존한다.
- 프로그램 파일 설치에는 다운로드가 필요 없다. 날씨·AI 같은 외부 서비스는 인터넷이 필요하며(안내 음성은 함께 담은 모델로 인터넷 없이 합성 — §8) 선택 기능인 받아쓰기 모델은 포함하지 않는다.
- 제작 전용 의존성: [Inno Setup 6](https://jrsoftware.org/isdl.php). 별도 앱 프레임워크 없이 표준 설치·제거 기능을 제공하기 위해 사용하며, 수신 PC에는 필요 없다.

Windows에서 재생성:

```powershell
$env:ISCC_PATH = 'C:\Program Files (x86)\Inno Setup 6\ISCC.exe'
npm run package:installer
```

소스 변경을 먼저 dev에 커밋해야 한다. 위 명령은 빌드 → 검증된 ZIP 내부 재료 생성 → EXE 순서로 실행한다. 사용자에게 줄 파일은 EXE이며 ZIP은 내부 포장 재료다. 코드 서명 인증서는 미설정이므로 Windows에서 게시자 확인 경고가 나올 수 있다.

## 0. 먼저 확인한 사실 넷

판단의 전제다. 전부 코드·저장소에서 직접 확인했다.

> **※ 정정(공개판):** §0~§7 은 2026-09-16 이전의 **제안** 기록이다. 그 뒤 한 것은 §8 에 있다 —
> 지금은 빈 PC 용 `CareCast-Setup.exe` 가 있고 설치 bat 은 `.git` 이 없으면 `git pull` 을 건너뛴다.
> `site-baseline.json` 은 공개판에 들어 있지 않다.

| # | 사실 | 근거 |
|---|---|---|
| 1 | **지금 설치 파일은 「설치」가 아니라 「업데이트」다** | 당시 `CareCast-설치.bat` 이 `git pull origin main` 으로 시작했다 — **이미 복제된 PC**를 전제한다. 첫 `git clone` 단계가 없다 |
| 2 | **자동 업데이트가 기관을 구분하지 않는다** | `autoUpdate.js` 는 (켠 PC 에서) 10분마다 `origin/main` 만 본다 — 공개판 기본은 꺼짐. 켠 기관이 둘이 되면 **우리가 커밋하는 순간 모든 기관이 10분 안에 받는다** |
| 3 | **음원은 이미 저장소에 없다** | `.gitignore:16` 이 `server/public/audio/` 를 막는다. DB(`*.db`)도 마찬가지다. 저장소 15MB 는 **코드만**이다 |
| 4 | **초기값이 운영 현장 값이다** | `server/config/site-baseline.json` — 다른 기관에 그대로 심으면 남의 시설 설정으로 시작한다 |

**그래서 「새 기관 배포」가 미착수인 진짜 이유는 설치 파일이 없어서가 아니라,
있는 것이 다른 일을 하는 물건이기 때문이다.**

## 1. 어떤 형식으로 배포할까 — 세 갈래

| 갈래 | 기관이 해야 할 일 | 막히는 곳 |
|---|---|---|
| **① git 기반**(지금) | Node 설치 · git 설치 · 저장소 접근 권한 · `git clone` | **기관 담당자가 git 과 GitHub 계정을 알아야 한다.** 요양원 실무자에게 이건 벽이다 |
| **② ZIP + 설치 마법사** ← **권함** | ~~Node 설치(한 번)~~ · 압축 풀기 · `설치.bat` 두 번 클릭 | 업데이트 경로를 따로 정해야 한다(아래 §4) |
| **③ 설치 실행파일**(Electron 등) | 실행파일 하나 | **로컬 AI를 못 쓴다** — 크롬 내장 Prompt API 는 패키징하면 사라진다(판단 기록 [진행중] 항목에서 이미 확인). 인터넷 끊겨도 돌게 하려던 설계가 무너진다 |

**② 를 권하는 이유**
- git 지식 요구가 사라진다. 실무자가 할 수 있는 일이 「압축 풀고 두 번 클릭」이 된다.
- ③ 과 달리 **브라우저에서 돌므로 로컬 AI 경로가 살아 있다.**
- 지금 구조(Node 가 `dist/` 를 서빙)를 **거의 안 바꾼다.** 새로 만드는 것은 포장 스크립트 하나다.

**무엇을 담나**: `dist/` · `server/` · `scripts/` · `package.json` · `default-baseline.json`(§2) ·
`설치.bat` · `docs/MANUAL-USER.md`·`MANUAL-ADMIN.md`.
**안 담는 것**: `.git/` · `server/db/` · `server/public/audio/` · `server/.env` · `site-baseline.json`(운영 현장 값).

## 2. 기본 셋팅값 — **가져갈 것과 절대 안 될 것을 가른다**

사용자 질문: *"배포할 때 우리 일정 중에 몇 개는 기본 셋팅값으로 가져가는 게 좋지 않을까?"*
**맞다. 다만 두 종류를 갈라야 한다.**

### 가져갈 것 — 어느 요양원에나 통하는 것

| 무엇 | 왜 |
|---|---|
| 자동방송 5종의 **구조** — 차임 → 안내 → 음원 → 배경음악 순서와 단계 구성 | 이 순서 자체가 현장 운영(2026-07-20~09-14 기록 57일)으로 다듬은 것이다. 빈 화면에서 시작하면 아무도 못 만든다 |
| 시각 **기본값**(07:50 · 08:40 · 11:15 · 16:15 · 18:00) | 어차피 마법사에서 고치게 한다. 빈칸보다 **고칠 값**이 있는 편이 낫다 |
| 볼륨 6채널 기본값 · 차임 유형 · 감시 유예(5분/60분) | 시설 특성과 무관한 값이다 |
| 방송 문안 **틀**(투약 안내·식사 안내 같은 고정 문안) | 어르신 이름이 없는 문안만 |

### 절대 가져가면 안 되는 것

| 무엇 | 가져가면 |
|---|---|
| `auto_shutdown_time`(현장 18:21) | **남의 PC가 저녁에 꺼진다.** 이미 `site-baseline.test.js` 가 제외를 고정하고 있다 |
| `audio_device`(현장 스피커 이름) | 그 이름의 장치가 없어 **Windows 기본 장치로 나간다** — 엉뚱한 데서 소리가 난다 |
| API 키 전부 | 저장소에 올라간다. 지금 그물이 셋이다(이름 목록 · 이름 생김새 · 값 훑기) |
| 환기방송 예약(09:10·09:20·12:00·12:10·17:00·17:10) | **그 시설의 동선**이다. 남의 건물에서는 뜻이 없다 |
| 기관명 · 어르신 이름이 든 문안 · 방송 이력 | 개인정보다 |

**새로 만들 것이 아니다.** `site-baseline.json` 을 뽑는 도구와 제외 규칙이 이미 있다
(`scripts/make-site-baseline.cjs` + `server/test/site-baseline.test.js`).
**운영 현장 값을 한 번 정제해 「보편 기본값」으로 만드는 일**이고, 그 결과를
`server/config/default-baseline.json` 으로 둔다(제안 — 아직 만들지 않음).

```
default-baseline.json   보편 기본값 — 배포판에 담긴다
site-baseline.json      그 기관의 값 — 배포판에 안 담긴다
                        (마법사가 받은 답으로 만들어진다)
```

심는 규칙은 **기존 그대로**다 — *"이미 값이 있으면 절대 덮어쓰지 않는다."*

## 3. 설치 마법사 — 한 장씩 넘기는 첫 설정

사용자 제안: *"지금의 큰 글씨 밑에 검색창처럼, 한 시트 한 시트 입력하면서 넘어가게."*
**재료가 이미 있다** — 큰 제목 + 한 줄 입력이라는 화면 문법(`HomeShell` + `HomeHeadline`)이
그대로 첫 설정에 맞는다. 새 디자인 언어를 만들 필요가 없다.

### 장 구성 (여섯)

| # | 묻는 것 | 왜 여기 있나 |
|---|---|---|
| 1 | **기관 이름** | 방송 인사말과 화면 제목에 쓰인다. 첫 장이라 부담이 없다 |
| 2 | **어느 스피커로 나갈까** | **지금 가장 자주 틀어지는 값이다.** 목록에서 고르게 한다(`audioDevices` 가 이미 목록을 준다). 안 정하면 Windows 기본 장치로 나간다 |
| 3 | **하루 방송 시각** | 5종을 기본값이 채워진 채로 보여 주고 고치게 한다 |
| 4 | **PC를 끌 시각** | **「안 끕니다」가 기본**이다. 모를 때 전원을 내리는 것이 가장 위험하다(2026-09-13 에 실제로 뚫렸던 자리) |
| 5 | **날씨 지역 · AI 키** | 없어도 방송은 나간다고 **화면에 적는다.** 나중에 넣어도 된다 |
| 6 | **소리 시험** | **차임을 한 번 울리고 「들리셨나요?」를 묻는다.** 설치가 끝났다는 것을 눈이 아니라 **귀로** 확인하는 유일한 장이다 |

### 규칙 넷

1. **한 장에 한 가지만 묻는다.** 두 개를 묻는 순간 「설정 화면」이 되고, 그건 이미 있다.
2. **기본값을 미리 넣어 둔다.** 빈칸은 「무엇을 적어야 하지」를 만들고, 채워진 값은 「이대로 둘까」를 만든다.
3. **「나중에」를 늘 둔다.** 요양원에서 설치 도중 전화가 온다. 끊겨도 잃는 것이 없어야 한다.
4. **안 끝낸 항목은 첫 화면에 남긴다.** 건너뛴 것이 조용히 사라지면 그게 제일 나쁘다 —
   특히 2번(스피커)을 건너뛰면 **소리가 엉뚱한 데서 난다.**

### 안 하는 것
- 마법사를 **끝내야만** 쓸 수 있게 막지 않는다. 막으면 급할 때 방송을 못 한다.
- 마법사가 **예약을 만들지 않는다.** 시각만 정하고, 실제 예약은 기존 화면에서 만든다 —
  두 곳이 예약을 만들면 언젠가 중복된다.

## 4. 설치판을 브랜치로? 저장소로? — **둘 다 아니다**

사용자 질문: *"저 설치 버전은 따로 브랜치를 또 따야 하나? 아니면 저장소를 따로 만들어야 하나?"*

**같은 저장소·같은 코드에 두고, 「빌드 산출물」만 따로 만든다.**

| 갈래 | 왜 안 되나 |
|---|---|
| 브랜치를 판다 | **두 곳을 다 고쳐야 한다.** 현장 버그를 고치면 배포판 브랜치에도 넣어야 하고, 한 번 빠뜨리는 날 갈린다. 이 저장소가 「같은 것이 두 벌」로 여러 번 데인 패턴이다(배포 게이트 시각 7곳, 볼륨 이름 3개) |
| 저장소를 따로 만든다 | 위와 같은 문제에 **이력까지 갈린다.** 더 나쁘다 |
| **포장 스크립트 하나** ← 권함 | 코드는 한 벌. `npm run package` 가 ZIP을 만든다. 설치판은 **코드가 다른 게 아니라 초기값과 포장이 다를 뿐**이다 |

**다만 기관이 둘 이상이 되는 순간 남는 문제가 하나 있다** — §0 의 사실 2번,
자동 업데이트가 기관을 구분하지 않는 것. [DEPLOY.md](DEPLOY.md) 가 권한 갈래는
**「현장 PC가 자동으로 받되, 어느 판을 받을지는 사람이 정한다」** 이다.
그건 브랜치가 아니라 **판올림 태그**로 푸는 문제다(예: `origin/main` 대신 `release/2026-09` 태그를 본다).

## 5. 제출은 무엇으로 — **코드 저장소 그대로 + 데모 시드**

사용자 질문: *"우리가 쓰던 거 음원이랑 같이 코드 있는 걸로 올려야 하나? 아니면 데모 버전으로?"*

### 먼저: **음원은 이미 안 올라가 있다**
`.gitignore:16` 이 `server/public/audio/` 를 막는다. DB 도 마찬가지다.
그러니 *"코드만 올린다"* 는 **선택이 아니라 지금 상태**다.

### 그리고 실제 음원·DB를 올리면 안 되는 이유 셋

1. **저작권** — 안내 녹음·동요·배경음악은 우리 것이 아니다. 재배포 조건을 확인하지 않았다.
2. **개인정보** — 방송 이력에 **어르신 실명이 들어간 문안이 실제로 있다**(생신 안내).
   내부 제출 문서에 그 사실을 적어 두었다(공개판 미포함). DB 는 제출 대상이 아니다.
3. **용량** — 부차적이지만, 음원을 넣으면 저장소가 코드보다 음원이 커진다.

### 권하는 제출 구성

| 무엇 | 담기나 | 비고 |
|---|---|---|
| 코드 저장소 | **그대로** | 음원·DB·키 없음. 지금 상태 그대로 |
| **데모 시드** | 넣는다 | 예약 몇 건 + **직접 만든 차임/짧은 안내 음성**. 심사자가 받아서 돌려볼 수 있게 |
| 실제 운영 화면 | **영상·스크린샷**으로 | 실제 음원을 올리는 대신 「돌아가는 것」을 보여 주는 길 |
| 매뉴얼 셋 | 넣는다 | 사용자 · 관리자 · 도입 |
| 발표 원고·슬라이드 | **안 넣는다** | 사용자 결정(2026-09-15). 저장소 공개 범위가 아직 미정이라 `.gitignore` 로 뺐다 |

**데모 시드의 음원은 우리가 만든 것만 쓴다** — 차임은 `carecast_chime.py` 가 **합성**하므로
파일이 없어도 나오고, 안내 음성은 TTS 라 문장만 있으면 된다. 즉 **남의 저작물 없이도
심사자가 소리까지 들어 볼 수 있다.**
