## 사용법

1. 아래 **[상시 규칙]** 을 복사한다.
2. 맨 아래 **[이번 작업]** 블록만 케이스에 맞게 갈아끼운다.
3. 한 번에 하나씩. 한 케이스가 통과한 뒤 다음으로 간다.

## [상시 규칙] — 항상 함께 붙일 것

```
[회귀테스트 작성 규칙 — 이 대화 내내 적용]

## 레벨
L1 단위   함수 하나. 시간 파싱, 반복 규칙 계산 같은 순수 계산
L2 통합   모듈 2~3개 연결. 예약 저장→스케줄러 트리거, 재생 배타 잠금, 큐 순서
L3 E2E    TTS·스피커·마이크까지 실제 입출력

원칙: 기본은 L2다. 상태 전이까지만 검사하고, 실제 소리 입출력은 타지 않는다.
그 경계(TTS, 오디오 출력, 마이크 입력)는 최소한으로 대체(stub)한다.
L3는 만들지 않는다 — 자주 깨져서 결국 아무도 안 돌리게 된다.
L1은 실제로 버그가 났던 케이스만 사후에 박아둔다.

외부 API(날씨·공휴일 등)는 테스트에서 실제로 호출하지 않는다.
대신 실패를 주입해서, 그래도 방송이 나가는지를 검사한다.

## 금지
- 한 번에 여러 케이스를 만들지 마라. 항상 하나씩.
- 범위를 스스로 넓히지 마라. 관련 케이스를 같이 만들지 마라.
- 테스트 하네스나 공통 유틸을 새로 만들지 마라. 기존 것을 쓴다.
- 레벨이 애매하면 만들지 말고 먼저 물어라.
```

## [이번 작업] 블록 — 케이스별

### 1호 (완료)

```

실제 방송 모듈에 맞게 import 경로와 함수명만 연결해라.
테스트 로직은 바꾸지 마라. 통과하는지 확인하고 멈춰라.

통과한 뒤, 수동재생도 같은 배타 잠금 경로를 타는지 확인하고
같은 파일에 케이스 하나만 추가해라. 새 파일을 만들지 마라.
```

```

검사 방법: 시간을 앞당겨(fake timer 등) 트리거 횟수를 센다.
```

```
[이번 작업]

아래 케이스 하나만 회귀 테스트로 만들어라.

케이스: 자동방송 시퀀스를 편집·저장하면 이전 러너와 예약 타이머가
       모두 정리되고, 실행 중인 러너가 한 벌만 남는다

         저장 후에도 1벌인지 확인한다. 실제 재생은 타지 않는다.

만들기 전에 먼저 확인할 것:
현재 시퀀스 진행 위치를 인덱스로 추적하는지, 항목 고유 ID로 추적하는지
코드에서 확인하고 알려줘라. 인덱스면 그 사실을 먼저 보고하고 멈춰라.
테스트는 그 다음에 만든다.
```

## 자동화되지 않는 것 — 사람이 눈으로 확인

배포 전 3가지만. 길어지면 실제로 안 하게 된다.

- [ ] 폰 마이크로 즉시방송 1회 → 스피커에서 소리가 나는가
- [ ] 그 직후 BGM이 원래대로 돌아왔는가
- [ ] 차임벨이 본방송보다 먼저 나오는가

나머지는 위 자동 테스트가 잡는다.

## 알아둘 것

**소리와 하드웨어는 자동화할 수 없지만, 그 직전의 상태 전이는 전부 된다.**
사고는 거의 항상 상태 전이에서 난다 — 소리가 안 난 게 아니라 잠금이 안 풀렸거나
두 개가 동시에 열린 것이다.

**순서 편집기 사고의 3대 원인**

| 원인 | 증상 |
|---|---|
| 진행 위치를 인덱스로 추적 | 순서를 바꾸면 이미 나간 항목이 다시 나가거나 하나가 건너뛰어짐 |
| 저장 시 기존 러너를 정리하지 않음 | 두 벌이 동시에 돌아 전 항목 중복 재생 |
| 실행 중 시퀀스를 그 자리에서 수정 | 진행 중인 항목이 사라져 큐가 멈춤 |

진행 위치를 인덱스가 아니라 **항목 고유 ID로 추적**하면 대부분 사라진다.
